# MediCare Playwright E2E

This project contains browser tests only. It does not alter application source, business logic, migrations, or the existing .NET test project.

## Isolation and safety

- The app URL is fixed to `https://localhost:5087`; a separate loopback HTTP health endpoint is bound to `localhost:5088`, and the Playwright web server refuses to reuse an existing listener. The test-only PFX certificate is self-signed, ignored by version control, and trusted only inside the Playwright browser context.
- Every Playwright process generates a unique `MediCare_PlaywrightE2E_<32-hex-run-id>` database name.
- Before the web app can start, `start-isolated-app.cjs` validates the generated run ID, database name, connection string, localhost URL, project path, and synthetic Admin test password. It then connects only to LocalDB `master` and checks that the generated database name is unused. Any failed check exits before spawning `dotnet`.
- The app receives only the generated LocalDB connection string. It runs in Production mode so Development-only demo patients, doctors, prescriptions, and appointments are not seeded. Existing migrations apply at startup only to this new database; no migration files are changed. A test-only synthetic Admin account enables the approval step in the booking scenario.
- Test databases are retained. There is no automatic database deletion or cleanup connection.
- Browser requests are allowed only to `https://localhost:5087`; external requests are aborted and recorded. Service workers and browser permissions are disabled.
- Test-only seed passwords are generated per run. Paymob, SendGrid, SMTP, Twilio, OpenAI, and Azure OpenAI credentials are overridden with blank/disabled local settings. SMTP is directed to local port 1 to prevent test-triggered mail from reaching a configured server.
- Patient accounts and booking notes generated by these specs are synthetic (`example.test`). Do not enter actual patient or payment data. Do not use the Development-only public Jitsi room.

## Test architecture

- `start-isolated-app.cjs`: preflight guard that runs before the app process and then launches it with sanitized local settings.
- `playwright.config.ts`: fixed localhost app process, sanitized provider environment, single worker, and per-test screenshots, traces, and videos.
- `support/fixtures.ts`: external-request blocking and per-test console, page-error, failed-request, and HTTP error diagnostics.
- `support/patient.ts`: synthetic account generation and real UI registration/login helpers.
- `tests/authentication.spec.ts`: patient registration/login/logout and invalid credentials.
- `tests/patient-booking.spec.ts`: creates a synthetic doctor, approves it through the Admin UI, creates schedule availability through the Doctor UI, then books through the Patient UI and verifies persistence after logout/login.

Screenshots, traces, videos, diagnostics, and HTML reports are written beneath this project’s ignored `test-results/` and `playwright-report/` folders when tests are eventually run.

## Not performed during setup

No application process, Playwright test, database connection, migration, payment, or external provider call is run by merely installing dependencies. The app starts only when a Playwright test command is run.
